# v0.1.0 — 一次判定，两条通道

第一个公开版本。

## 为什么

一个 Harness 装两个通知插件就等于有两个分类器：手机说「第 12 轮结束」，浏览器说「完成」，一次授权来两条，子 agent 的动静两边都漏。`dsh-notify` 在宿主侧只判定一次，再把同一个判定分发给每一条通道。

## 有什么

**浏览器** —— 系统通知，每种事件有自己的音效，点击跳回对应会话，同类合并，而且你正在看那个会话时保持安静。

**手机** —— Bark 推送，可配分组、每种事件独立铃声、可选深链回界面；浏览器关着也收得到。

**读起来像对话** —— 标题是状态标记加会话名，正文是你最后一次输入的提问，失败时追加原因。

**一个事件模型** —— `completed`、`failed`、`interrupted`、`approval`、`question`。只有宿主确实这么说时，一轮才算「完成」；`blocked`、`max-tokens`、`forked` 以及未知的结束方式一律保持安静，不会为没干完的活把你叫起来。

**不吵** —— 一次完成会等 900 毫秒，让紧跟着的自动续跑把它取消掉；子 agent 会话默认静默；同一件事最多一张卡片加一次推送；每会话 6 次/分、全局 20 次/分作为风暴刹车。

**朴素地安全** —— 一切都走 Connection 的鉴权 `/api` 栅栏。设备密钥从不进浏览器：页面只看到 `configured` 加后四位，回显掩码会保留已存的值，只有显式传 `null` 才会清除。

## 安装

```sh
dsh plugin --profile web add @yaorenliang/dsh-notify
```

刷新页面，打开 **设置 → 会话通知**，粘贴 Bark 密钥，在每个通道上各点一次 **测试**。profile 会热应用这个 bundle，不需要重启。

## 从两插件方案升级

不会自动删除任何东西，也不会自动搬运任何东西：打开一次设置页，粘贴 Bark 密钥，等新页面看起来对了再删掉旧插件。前身插件自己的文档留在原处。

## 已知限制

断线的浏览器不做重放；一个 profile 只服务一个人；macOS 上只验证过 Chrome。
